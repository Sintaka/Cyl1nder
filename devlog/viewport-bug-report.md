## v0.1.00037 补充（2026-08-11）：本轮 viewport/nodeview 踩坑

### A. 4 条无头线段（node graph 残留，不是 viewport 渲染问题）
- 现象：node view 初始位置有 4 条独立线段，把 `_input_`/`_output_` 挪开才看见。
- 根因：快照 `scene/node-graph.json` 出现 **1 节点 + 4 悬空连接**（source/target 指向不存在的节点 id）。rete2 `editor.removeNode()` 不会可靠移除挂在该节点上的连接 → `restoreGraph` 重建后旧边残留为"孤儿连接"；`serializeGraph` 又把它们原样写回 → 恶性循环。
- 修复：`restoreGraph` 先 `removeConnection` 清掉**所有**存活连接再删节点；`serializeGraph` 只序列化两端节点仍在的边（防御）。实测用户 serial（旧快照 1 节点/4 悬空 conns）恢复后连接数=0，无头线段消失。
- 教训：序列化/恢复的"干净重建"必须显式清连接，不能假设 removeNode 会带走连接；写入端要防御（孤儿边不落盘）。

### B. 显示模式下拉菜单错位/被 dock 截断
- 现象：菜单出现在右下方、被 docking 面板截掉；单击立即关闭。
- 根因：`.cyl-mode-menu` 是 `position: absolute`，left/top 用 `getBoundingClientRect()`（视口坐标）→ 相对最近定位祖先定位，落在 dock 面板 overflow 裁剪区外。
- 修复：`position: fixed`（视口坐标天然匹配）；交互改为 pointerdown 记录起点，pointerup 位移 >4px 判定为"拖动"（应用悬停项并关），否则"单击"（持久显示，点项/点外部关闭，再点按钮 toggle）。
- 注意：`document` 捕获阶段 pointerdown 关菜单，要排除 modeBtn 与菜单内部，否则点按钮先被 document 关掉。

### C. 相机缩放是 fov fake（改真位移）
- 旧：wheel/Alt+右键 改 `cam.zoom` 再 updateProjectionMatrix（fov 视角假缩放，行为像"拉近拉远"但不是真位移）。
- 新：`dollyCamera()` 沿视线方向移动相机位置（0.2~200 钳制），wheel `delta*0.02`、Alt+右键 `delta*0.5`；`cam.zoom` 恒 1。与 AHS 视口一致。

### D. display 只显示第一端口
- `_input_` display → `setDisplayFocus("inputs", 0)`（只显示 in0）；`_output_` display → `setDisplayFocus("outputs", 0)`。默认新图 `_input_` 点亮 → 视口只画 in0，不再四路同显。

### E. 右上 4 状态按钮贴角
- 14x14 正方形；chips 容器 `margin:-4px -6px 0 6px` 顶到节点右上角；最右 chip `border-top-right-radius:6px` 匹配节点圆角。
- 坑：`.cyl-rp-head` 有两处定义（基础 113 行 + 节点头部 219 行），后者 `align-items:center` 覆盖前者 → 必须先改**后者**（flex-start），否则负 margin 无效、chip 垂直居中。
- display 蓝 ring（`box-shadow 0 0 0 1px #60a5fa`）优先于选中黄：`.displayed.selected` 用更高特异性（0,2,0）→ 蓝 ring + 外圈淡黄 `rgba(253,224,71,.4)` 共存可见；`.selected` 单独时降为半透明淡黄。

## v0.1.00038 补充（2026-08-11）：相机 dolly 踩坑
- 现象：① 相机贴近原点/目标后拉不回来；② 一直滚轮放大在某一点反复横跳。
- 根因（`web/src/viewport/controls.ts` `dollyCamera`）：旧实现 `dir = target - cam.position`，当 dist<0.001 直接 return（卡死）；更糟的是 dist 接近 0 时 `dir.normalize()` 对零向量产生 **NaN** → 相机位置 NaN → 渲染跳变。且距离钳制下限 0.2 与目标过近时会在"钳制值"与"实际距离"之间弹跳。
- 修复：dist<1e-4 时退回 `cam.getWorldDirection().negate()`（从不 NaN）；统一用 `cam.position = target + dir * (-next)`，`next = clamp(dist - amount, 0.05, 500)`，距离单调；焦距固定（fov/zoom 永不改）。
- 验证：wheel-in 200 次距离 5.41→0.05 单调不翻转、全有限；wheel-out 400 次 2.45→500 恢复；cam.zoom 恒 1。
- 教训：dolly 公式必须把"距离目标"作为不变量（position 由 target+dir*dist 重建），而不是在旧位置上加增量；零向量归一化前必须兜底。
