# 主脑行为校准（每轮收尾必做）

这份文件**不是**给子智能体看的（那是 `SUBAGENT_BRIEF.md`），是主脑（主管智能体）
用来纠正自己行为的。核心问题：主脑的思考是最贵的资源，但它天然倾向于自己动手 ——
因为自己动手的**下一步**总是最确定的，而派发要先写任务书、还要复核回报。
这个倾向必须靠机制对抗，不能靠自觉。

## 每轮任务收尾三步（Retro）
任务做完、提交之后，**不要直接结束**，回头看执行过程：

1. **点数**：这一轮里同一类操作我重复了几次？（按工具调用数数，不按印象）
2. **归层**：每一类落在三层分流的哪一层（判据见 development-standards.md）。
   落在第 1 层（确定性、零上下文）而我却自己跑了的 —— **就是这轮的欠债**。
3. **还债或记账**：能一次脚本化的当场做掉；做不掉的写进本文件「待固化」，
   并在下一轮开工前先看一眼。

短期这会多花 token；固化之后每轮省下的是**几十次工具调用加同等份量的思考**。

## 已固化（手跑它们的等价物 = 回归）

|---|---|---|

| 活体巡检（桥/vite/MCP + registry 基线 + 关键值延迟） | **`node scripts/probe-live.mjs`** | ~5 次 |

`probe-live.mjs` 用法：裸跑只报告；带 `--projects=N --serials=N --channels=N`
则**断言基线**（查测试泄漏用，不符即 exit 1）；`--value=<url>` 可重复，
对每个 URL 连读 4 次报耗时（看锚点冷启动「首读慢、后续快」的特征）。
本会话基线是 `--projects=1 --serials=2 --channels=11`，**实测通过**。

## 又一条：熟悉的缺陷形状会让我跳过验证（2026-08-21，当轮实犯）
`probe-live.mjs` 交付后我跑了一次，看到「exit 0 且没有任何输出」，
当场判定它是**空扫描谎报**（本会话修了一整轮的那个形状），并写下了这个结论。

**这个指控是错的。脚本一直是好的。** 输出被吞掉的原因是我在同一个 pwsh 调用里
**在 `node ...` 后面又跟了一条语句**（`"=== probe exit: ... ==="`）——
单独跑 `node scripts/probe-live.mjs`，汇总表、六行 OK、`ALL GREEN` 全都在。

而且我为此提的「`process.exit()` 不 flush stdout」假设也被我自己的实验**否证**了：
40 条 `console.log` 后接 `process.exit(0)`，一条不少。

**两层教训**：
1. **测量装置本身会骗人**。这与「手搓 grep 误报 5 次」同源：
   我又一次把**仪器的故障**当成**被测物的缺陷**。判缺陷前先确认仪器是干净的 ——
   最省的办法就是**让被测命令单独跑，后面什么都不接**。
2. **越熟的缺陷形状越危险**。我刚花整轮修「谎报成功／空扫描报绿」，
   于是看到「exit 0 + 无输出」就直接归档进那一类，**跳过了验证**。
   模式识别省下的是思考，但省掉的那一步恰恰是判断。
   → 判据：**当我觉得「这我见过」时，就是最该多验一次的时刻。**

## 固化脚本本身的两条硬约束（踩过才知道）
1. **编排脚本必须是 `.mjs` 用 `node` 跑，不能是 `.ps1`**。`pwsh` 不在 harness 可信前缀名单里
   （`git`/`node`/`npm`/`pnpm`/`hython`/`.venv\scripts\python` 才是），
   `pwsh -File` 的子进程继承沙箱限制 → pytest 在 `mktemp` 处 460 个 `PermissionError`、
   vitest 在 esbuild 命名管道处 `spawn EPERM`。**同一套命令直接跑全绿。**
2. **脚本自报 exit 0 不算数，要验它真的改了东西**。`release-step.ps1` 第一版打印
   `== 6/6 完成 ==` + exit 0，而版本号没变、索引没生成 —— `$Args` 是自动变量，
   当参数名被遮蔽成空数组，`& node @Args` 退化成裸 `& node`，而裸 `node` exit 0。
   细节见 `development-standards.md`。

## 反模式清单（本会话实际犯的，按代价排序）
1. **确定性事实交给 LLM 判定**。子智能体报「变异 2 条红」实为 **4 条**（还漏报一条既有测试
   在守护 bug）；子智能体在注释里写错版本号 **4 次**。
   → 确定性事实**交脚本**，退出码不需要复核；交智能体拿到的是"它对事实的报告"，
   可信度低于事实本身，还得复核一遍，**净亏**。
2. **手搓一次性检查代替脚本**。我的 grep 误报 5 次，最后一次**打红了我照样提交**。
   → 一个被训练成可以忽略的检查，比没有检查更坏。
3. **在内部事件后重发完整报告**。含 8 行缺陷表的完整报告写了 **3 次，前 2 次多余**
   （写完又派了新活，工作根本没结束），约 2000 输出 token 加两次组织成本。
   → 报告只在**用户可见的里程碑**发一次；工作还要继续就别写结论。
4. **忙等子智能体**。`list_agents` 轮询 **6 次**，而系统明确说完成会通知。
   → 等通知；等待期做独立的活，最多一行说发现了什么。
5. **任务书里写没核实过的标识符**。我要求用 `elideMiddle`/`elidePath`，实际只有
   `elide`/`elideEnd`（子智能体 grep 后用对了）。
   → 具体标识符要么先 grep 确认，要么写成「用该模块现有的 X，名字自行确认」。
6. **只看自己那一层就下结论**。同一课在一个会话里撞四次：没看执行上下文、只验端点没验面板、
   只看类型签名不看实现（`??` 的语义与签名给的印象相反）、只看代码形状不看它在链条里的方向。
   → 判断"数据会不会丢"必须读到**赋值那一行**；判断"用户症状是否消失"必须走到**用户看的那一层**。
7. **换了马甲的忙等**。我在本文件里禁了 `list_agents` 轮询，紧接着改用
   `Test-Path` + `git status` 去轮询子智能体的产物文件 —— **一轮内 8 次**。
   → 规则的对象是**等待行为本身**，不是某个工具名。禁的是「除了等什么都不做」，
   不是禁 `list_agents`。等待期只有两个合法动作：做**独立**的活，或收尾。

   **写完这条之后我又犯了两次**（同一轮内连续 3 次 `Test-Path commit-step.mjs`）。
   三次同一条规则 —— 说明**这条规则写成「纪律」是无效的，必须写成「机制」**：

   > **子智能体完成是被 runtime 推给我的，我永远不需要去查。**
   > 所以「独立的活做完了」的正确动作不是找点什么来查，而是**结束本轮**——
   > 通知会在下一轮自己到达。

   为什么原来的写法不管用：轮询的**触发点**不是「我想偷懒」，而是
   「我不知道现在该不该继续」。一条要求我「静默做独立的活」的纪律，
   在**独立的活已经做完**时没有给出任何合法动作，于是我就去查状态填空白。
   补上「没活了就收尾」这个出口，轮询的动机才消失。
   **一条没有给出替代动作的禁令，等于没有禁令。**
8. **诊断时跑全量套件**。为了看「pytest 在 `pwsh -File` 下会不会 PermissionError」，
   我把 460 例全量套件跑了**两遍**，每次约 15KB 输出被截断刷掉大量上下文 ——
   而**一个测试文件就能给出同样的答案**。
   → 诊断的目的是**观察一个现象**，用最小充分命令（`-x`、单文件、`--no-header`）；
   全量套件是**验收**用的，不是探路用的。这条和「周期性结论要在远大于周期的窗口上验」
   互为镜像：**验收要大，探路要小。**

## 主脑应该留下的（第 3 层）
回头看，这一轮真正只有主脑能做的都很短：
- 判断 ~1s 是「轮询周期的一半」而不是某处慢；
- 看出一条**常绿测试的 docstring 把 bug 写成了规格**（所以谁修都会"打红"然后撤回）；
- 判断读侧「跳过通道」是合理降级、**刻意不修**（写侧同形状却是撒谎）；
- 纠正自己关于 `client.ts` 的错判；认出心跳节流是故意的限流而不是 bug。

**注意其中两条是"拒绝行动"**。第 3 层的高价值输出经常长这样，
而它最容易被"顺手修一下"的冲动吃掉 —— 这也是为什么第 1、2 层必须交出去：
省下来的不是时间，是**判断力的预算**。
